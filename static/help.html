Quickstart Deployment Guide

Get your artwork display engine running in minutes using Docker. This is the recommended method for most users as it bundles all dependencies (Python, Database, and Web Server) into a single, isolated container.

Prerequisites

  • Docker: Installed and running on your host machine.
  • Docker Compose: (Included with Docker Desktop on Windows/Mac, may need separate install on Linux).

Installation Commands

Open your terminal and run the following sequence to clone the repository and start the engine:

# 1. Clone the repository
git clone https://github.com/AiwendilInTheWoods/Screen-Docent.git

# 2. Enter the directory
cd Screen-Docent

# 3. Build and start the container in detached mode
docker compose up -d --build
Data Persistence: Your database and artwork library are stored in persistent Docker volumes (mapped to the ./Artwork and ./data directories on your host). This means you can safely update the application via git pull and a rebuild without losing your settings or uploaded images.

First Steps

Once the container is healthy, you can access the different parts of the system via your browser:

  • Admin Dashboard: http://localhost:8000/admin — Start here to create your first playlist and upload high-resolution images.
  • Main Display: http://localhost:8000/ — Point your TV or monitor browser here to begin the artwork loop.
  • Mobile Remote: http://localhost:8000/remote — Access this on your phone to control the playback from your couch.

AI Curator Agent & Review Workflow

The engine features an autonomous AI pipeline that acts as a digital curator, analyzing your artwork and generating high-quality metadata for the "Museum Placard" display.

Connecting a Model — the AI Engine panel

The easiest way to plug in a model is right in the app: open Admin → ⚙ Settings → 🧠 AI Engine. Pick a provider, paste an API key (or sign in), choose a model, and click Test & Save. The key is validated against the live provider before it's stored, and changes take effect within seconds — no file editing, no rebuild.

  • Google Gemini — free tier is plenty for personal use. Get a key →
  • OpenAI (GPT-4o family) and Anthropic (Claude) — paste your provider key.
  • OpenRouter — click Sign in with OpenRouter for one-click setup (no key to copy), then reach every major model through a single account.
  • Local / Ollama / LM Studio — point the Base URL at your own OpenAI-compatible server (inside Docker, use host.docker.internal instead of localhost); no key needed.
How it works: every provider is reached through one OpenAI-compatible endpoint, so configuration is just base URL + key + model. The Advanced section lets you use a separate (cheaper/faster) model for search classification, override the Base URL, or set a temperature.

Alternative: the .env file

If you prefer, you can seed a default key before first run with a .env file in the project root (ignored by version control). The AI Engine panel always overrides this when set.

# Optional fallback for the AI Curator Agent
GEMINI_API_KEY=your_free_key_here

The AI Curator Pipeline

When you upload an image via the Admin Dashboard, the following automated workflow is triggered in the background:

  • Visual Analysis: The backend agent sends an optimized version of the image to the Vision model.
  • Metadata Generation: The AI generates a museum-grade Title, a Contextual Description (2-sentence historical or artistic blurb), and a set of Descriptive Tags.
  • Database Entry: This information is saved alongside your image, awaiting your final approval.

The 'Pending Review' State

To ensure accuracy and prevent AI "hallucinations" from appearing on your displays, all newly ingested art is placed in a Pending Review state. This acts as a human-in-the-loop safety mechanism.

  • Navigate to the Review Queue tab in the Admin Console.
  • Review the AI-generated titles and descriptions. You can edit any field to correct historical facts or artistic interpretations.
  • AI Guidance & Regeneration: If the AI completely misses the mark, you can provide context in the "AI Guidance" field (e.g., "This is actually a family photo from 1995") and click Regenerate. The agent will rebuild the metadata using your specific facts.
  • Click "Approve & Publish" to move the artwork into the live display rotation.
RAG Enrichment & Discovery:
  • RAG Enrichment: Use the "Batch Enrich" button to cross-reference your collection with Wikipedia. The AI will fact-check existing metadata and rewrite descriptions using verified historical context.
  • Art Scouts: Use the "Discover" tab to find new high-resolution, public-domain masterpieces from world-class museums like the Art Institute of Chicago.
Swapping Models
Gemini is the default for its high performance-to-cost ratio, but you can switch to OpenAI (GPT-4o), Anthropic (Claude), OpenRouter, or a local model at any time from ⚙ Settings → 🧠 AI Engine — no code changes required. All enrichment and search calls follow the model you select.

URL Parameters Reference

Append these parameters to your display URL (e.g., http://SERVER:8000/?display=tv_01&rotate=true) to override localized behavior.

Parameter Description Example
rotate Forcefully rotates the entire DOM by -90 degrees. Useful for TVs mounted vertically where the OS remains in landscape mode. rotate=true
display Assigns a unique ID to the display. This ID allows the Mobile Remote to target this specific screen. Defaults to default. display=living_room
cycle_time The number of seconds between artwork transitions. cycle_time=60
mode Overrides the visual rendering mode. Options: ken-burns, static-crop, contain-matte. mode=contain-matte
shuffle Randomizes the playback order of the current playlist. Options: true, false. shuffle=true
placard_wait Seconds to wait after a new image loads before the info placard slides in. placard_wait=5
placard_show Seconds to keep the placard visible during its initial entrance. placard_show=20
placard_manual Seconds to display the placard when manually triggered by the remote or user interaction. placard_manual=15

The Mobile Remote Control

The remote console is accessible at /remote from any mobile browser on the same network.

  • WebSocket Routing: The remote uses WebSockets for instant control. When you change a playlist or mode on the remote, the targeted TV updates immediately without a page refresh.
  • Target Selection: Use the "Target Display" dropdown at the top of the remote to select which screen you want to control. Displays appear in this list as soon as they are opened in a browser.
  • Instant Actions: The remote provides dedicated buttons for Next/Previous artwork and a "Show Placard" button to quickly identify pieces.

Raspberry Pi Appliance (Recommended for TVs)

The easiest way to drive a TV or monitor is a dedicated Raspberry Pi that boots straight into the full-screen display — no browser chrome, no manual URL entry, and no third-party kiosk app. Flash a card, point it at your server, and forget it. (A Pi 4 is plenty for display-only; a Pi 5 with 8 GB is recommended if you also run the server on it.)

1. Flash Raspberry Pi OS Lite

Use Raspberry Pi Imager to write Raspberry Pi OS Lite (64-bit) to a microSD card. Before writing, open Edit Settings and set:

  • Hostname (e.g. docent-living-room)
  • Enable SSH (password or public key)
  • Username + password (your one-time login)
  • Wi-Fi SSID + password + country (so it joins the network headless)
  • Locale / timezone

2. Run the installer

Boot the Pi (no keyboard or monitor needed), SSH in, and run:

git clone https://github.com/AiwendilInTheWoods/Screen-Docent.git
sudo Screen-Docent/deploy/appliance/install.sh

This installs cage + Chromium as a kiosk, sets it to launch on boot, disables screen blanking, and writes a config file to the SD card's boot partition.

3. Configure the display

Edit screen-docent.conf on the card's boot partition (visible on any computer — no SSH needed), then reboot:

SERVER_URL=http://192.168.1.50:8000   # your Screen Docent server
DISPLAY_ID=living_room                # unique name shown in the remote
MODE=                                 # optional: ken-burns|static-crop|contain-matte
CYCLE_TIME=                           # optional: seconds per image

The Pi comes up full-screen on the Canvas. If the server isn't reachable yet, the screen stays black and paints automatically once it is.

All-in-one (server + display on one box)

For a single-frame setup with no separate server, set ALL_IN_ONE=1, SERVER_URL=http://localhost:8000, and your GEMINI_API_KEY in the config, then re-run the installer. It installs Docker and runs the server on the same Pi.

Full reference: deploy/appliance/README.md in the repository covers everything, including the X11 fallback and on-device troubleshooting.

e-ink & "Dumb" Frames (Image API)

Low-power e-ink and "bring-your-own-server" frames don't run the browser display at all — they just fetch a server-rendered image on a wake schedule. This covers DIY ESP32 + Waveshare panels, Pimoroni Inky Impression, a TRMNL in BYOS mode, or any device (even a tiny script) that can perform an HTTP GET on a timer. The server crops to your panel size and Floyd–Steinberg-dithers to the device palette.

The endpoint

GET /display/{display_id}/current.png?playlist=Masterpieces&w=1600&h=1200&palette=spectra6
ParameterValues
display_idA unique name for this frame (path segment)
playlistCollection name (defaults to the first playlist)
w / hYour panel's pixel dimensions
palettespectra6, acep7, gray4, gray16
fitcover (fill, default) or contain (letterbox)
formatEnd the path in .png (default) or .bmp (firmware without a PNG decoder)

Each request advances to the next image, so the frame's wake interval becomes its rotation. The response's X-Refresh-After header tells the frame how many seconds to deep-sleep before fetching again.

How to set up a generic "dumb terminal" frame

Any device that can GET a URL on a timer works. The pattern is always the same: wake → GET the image sized for your panel → display it → sleep for X-Refresh-After seconds. A Raspberry Pi driving any panel from the framebuffer can do it in a few lines:

#!/bin/sh
SERVER=http://192.168.1.50:8000
DISPLAY_ID=hallway
PALETTE=spectra6          # spectra6 | acep7 | gray4 | gray16
W=1600; H=1200            # your panel size

while true; do
  # Fetch the next image (headers -> /tmp/h, body -> /tmp/art.png)
  curl -s -D /tmp/h -o /tmp/art.png \
    "$SERVER/display/$DISPLAY_ID/current.png?w=$W&h=$H&palette=$PALETTE"

  # Show it (framebuffer example; swap in your panel's render command)
  fbi -T 1 -noverbose -a /tmp/art.png

  # Sleep for the server-suggested interval (fallback 300s)
  SECS=$(awk -F': *' 'tolower($1)=="x-refresh-after"{print $2+0}' /tmp/h)
  sleep "${SECS:-300}"
done

On a true e-ink microcontroller (ESP32 + Waveshare, Inky, etc.) the same flow runs once per wake: connect Wi-Fi → GET .../current.bmp?... → push the bytes to the panel → read X-Refresh-After → deep_sleep() for that many seconds. Request .bmp if your firmware can't decode PNG.

Already-shipping example: a TRMNL in BYOS mode already polls a server, downloads an image, and deep-sleeps for a refresh interval — point its server URL at this endpoint and it works as-is.

Hardware & Kiosk Best Practices

For a seamless "Museum" experience, your display should behave like a native appliance rather than a browser window. The recommended way to get there is the Raspberry Pi Appliance above — the options below are for reusing an existing TV stick instead.

Bring-your-own TV stick (fallback)

  • Android / Fire OS: Fully Kiosk Browser lets you lock the TV to a specific URL, hide all toolbars, and prevent the screen from sleeping. (A dedicated Pi appliance avoids needing this third-party app.)
  • Android TV: TV Bro is a great open-source alternative that handles full-screen web apps well on leanback devices.
Pro Tip: Most smart TVs have an "Auto Power Off" setting. Ensure this is disabled to prevent the artwork from stopping after a few hours of "inactivity."
